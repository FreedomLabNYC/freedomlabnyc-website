Primary tool: gws

googleworkspace/cli is the cleanest general command surface we have used. It builds commands from Google's Discovery Service, returns structured JSON, supports schema inspection and dry runs, and ships agent skills.

Important: the project says it is not an officially supported Google product and remains pre-1.0. Pin a tested version for production automation.

# Install
brew install googleworkspace-cli
# or: npm install -g @googleworkspace/cli

# Authenticate
gws auth setup
gws auth login -s drive,gmail,sheets,docs,calendar
gws auth status

# Discover before guessing
gws drive --help
gws schema drive.files.list

# Read a Sheet range
gws sheets spreadsheets values get \
  --params '{"spreadsheetId":"SPREADSHEET_ID","range":"Sheet1!A1:D10"}'

Do not print unmasked exported credentials in an agent-visible terminal, log, document, screenshot, or chat.

Agent operating loop

  1. Confirm identity and scope. OAuth consent and Cloud API enablement are separate gates.
  2. Resolve the exact target. Use stable IDs, not names or titles alone.
  3. Fetch current state. Avoid stale copies.
  4. Prepare the smallest mutation. Preserve user-managed content and formatting.
  5. Dry-run or render a diff. Show target, changed fields, and dedupe key.
  6. Apply once. Make retries idempotent.
  7. Read back. Verify Google's stored object, not only the success response.
  8. Check the human surface. Required for formatting, drafts, calendars, and Admin settings.
  9. Return stable proof. IDs and URLs, never credentials.

Service playbooks

Gmail

Search narrowly, fetch full bodies only for relevant message IDs, and persist message/thread IDs for deduplication. Draft by default. Before sending, verify the recipient, subject, body, attachments, and target thread.

users.watch → Pub/Sub historyId → users.history.list
→ changed message IDs only → idempotent processor

Renew the watch before it expires. Pub/Sub is a wake-up signal, not the email body.

Sheets

Inspect headers, section boundaries, formulas, validation, and duplicate identities first. Use bounded value updates for cells and batchUpdate for row insertion, formatting, rich links, checkboxes, or validation. Read back the exact rows.

Docs

Edit the existing working Doc. Fetch its current structure, make targeted batchUpdate requests, apply multiple replacements bottom-to-top, and account for UTF-16 indices. Re-fetch to verify text, links, and styles.

Drive

Use gws for search, metadata, permissions, native file creation, and small uploads. Use rclone for large trees:

rclone copy ./archive gdrive:Agent-Archive \
  --transfers 4 --checkers 8

For archives, copy is safer than sync because local deletion does not remove remote files. Verify destination counts and representative sizes or hashes.

Calendar

Use bounded windows and explicit ISO 8601 timezones. Dedupe with a source URL plus provider event/occurrence ID. Re-fetch before RSVP or update, mutate only owned fields, then read back the stored event.

Meet

Keep Calendar/API authorization separate from the browser attendee identity. Use a dedicated account/profile, transparent bot name, organizer rules, bounded join windows, and visible transcription notice. Transcript delivery is complete only after the destination document is created and read back.

Workspace administration

Distinguish organization settings from user preferences. Use the exact Admin console deep link and official help page, identify the required privilege, confirm risky identity/routing/security changes, and verify the affected Workspace surface after any propagation delay.

Security and privacy

  • Request only the services and scopes the workflow needs.
  • Use drive.file when an app should access only files it creates or the user explicitly opens/shares with that app.
  • Keep OAuth secrets, refresh tokens, service-account keys, and exported credentials outside Git.
  • Prefer an OS keyring or secret manager. If a credential file is unavoidable, use owner-only permissions.
  • Never publish authorization codes, cookies, signed callback URLs, real account IDs, object IDs, or production payloads.
  • Scan both source files and the final packaged archive before release.
